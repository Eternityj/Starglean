- 已完整获取并验证的正文与照片形成当前账号的内存快照；切换其他应用时不再调用关闭，不清空笔记，返回后继续显示同一篇。首次发现仍需真实位置与服务端打开确认。

- 新包替换会话、发布恢复日志、云日记关联文件的六处不兼容读取；文件读取使用 8 KiB 缓冲、严格总字节上限，长度帧使用 `readFully` 拒绝截断。保留现有 AES/GCM、AAD、alias、AtomicFile、文件版本与路径，不删除旧登录信息、日记或草稿。
- Android 12 启动画面属性移入 `values-v31/splash-theme.xml`，旧系统使用同色背景。`assembleRelease` 现在依赖完整 `lintRelease`；不会再仅靠未包含 NewApi 的 lintVital 交付。完整检查为 0 errors、25 warnings、4 hints，不声称全部警告已清除。
- 新版在 API 30 和 API 35 的账号/存储组各 7 项通过：真实 Keystore 往返、损坏证据保留、注册与登录两种 OTP intent 的验证后持久化及新 store 恢复、并发刷新、云日记链接、发布恢复日志及照片下载。OTP 响应由隔离的本地 transport 提供，未发送邮件、未伪造生产登录状态，不能替代用户手机真实验证码复测。
- 两个系统的导航/门禁测试各 1 项通过。API 35 初跑因测试用硬件 BACK 可能关闭 Activity 导致超时；已改为明确隐藏 IME、等待稳定及保存失败证据，重跑通过。API 30 的只读 AVD 名属性与新版不同，测试已支持两个系统的属性名，仍只允许指定独立 QA 模拟器。测试包修改不进入分发 APK。
- 已检查 API 30 实际截图：登录页完整、数字键盘展开时验证码输入与验证按钮均在键盘上方；API 35 本轮输入法呈现紧凑浮动工具条，不能把该截图算作完整数字键盘覆盖。历史完整键盘截图只作历史记录，不代替本轮 API 30 的实际检查。
- 已在 API 30 从旧包直接覆盖安装新包成功，包名与签名证书保持一致；没有卸载或清空数据。详细复现、测试及静态检查记录保存在 `app/build/compat-qa/`。
