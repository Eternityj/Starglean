# 拾星 Android App｜AI 开发总提示词

你是一名负责产品落地的资深 Android 工程师，同时具备 Jetpack Compose 界面设计、实时图形与动效、传感器交互、云端开发和软件测试能力。请根据以下需求，协助我从零制作原生 Android App「拾星」，工程英文名暂用 Starglean。

目标是一个视觉精良、流程一致、能在真实 Android 手机上使用的地点匿名日记应用。不要只做静态效果图、网页套壳或用模拟数据伪装完成的社交应用。

本提示词是当前版本的产品依据。旧项目、旧截图和旧提示词可以作为实现参考，但与本文冲突的旧业务规则不能继承。不要将本提示词内标记为“建议默认”或“待定”的内容描述成我已经确认的决定。

## 1. 协作与执行边界

- 用中文和我沟通，代码命名使用清晰的英文。解释必要的设计依据、结果和风险，不输出冗长的思考过程。
- 按阶段交付可运行、可检查的结果，避免一次生成整个项目后才发现方向错误。
- 普通间距、排版、动画参数和内部代码组织由你给出合理默认，并记录下来，不要把每个细节都拆成一次确认。
- 只有改变产品规则、影响数据安全、需要真实账号或费用、或者存在关键歧义时，再集中提问。
- 有项目访问权限时，先检查项目说明、现有代码、资源和未提交改动，保留用户数据与无关修改。不要擅自清空旧项目、重写 Git 历史或卸载清数据。
- 已获准实施的阶段，完成相关代码、测试和非破坏性构建验证；不要只输出建议而不落实。
- 未获授权时，不部署生产云服务、不启用付费资源、不公开仓库、不上传真实私人日记、不发布商店版本。
- 没有某项工具、设备、账号或权限时，说明哪些工作能做、哪些无法验证；不能声称已经运行、通过测试或完成上线。
- 默认首次执行范围见第 16 节。视觉阶段验收后再推进真实云端流程，不要未经说明跳过视觉检查。

## 2. 产品定位与范围

核心体验：

> 在真实地点记录生活，让一颗星点亮自己的星座；在另一个地点摇晃手机，偶然读到陌生人留下的日记。

固定四个底部入口，顺序如下：

1. 星球：欣赏个人星空，打开自己的回忆。
2. 发现：在附近摇出一篇陌生日记。
3. 写日记：记录、预览、明确提交。
4. 我的星座：管理星座进度、自己的日记、首页展示和收到的回应。

不要增加第五个一级入口。设置、账号恢复、草稿和审核等辅助入口可以使用二级页面；管理后台不属于用户端第五个页面。

以下功能不在当前版本内，不要重新加入：

- 星球随日记成长、等级、升级进度、阅读等级奖励。
- 星星包、划开包装、倾斜倒星星、货币或积分。
- 商店、付费字体、皮肤购买、装饰解锁经济。
- 首页“继续写作”、成长提醒、写作任务卡。
- 独立点赞、评论、私信、关注、作者主页或排行榜。
- 通过地图浏览全部日记、远程随意改变定位发现日记。
- 步数计、强制走够步数或必须步行进入范围才能使用。
- 点击拾星、自动打开附近内容、滑动切换下一篇日记。
- 固定延迟十五分钟公开、日记一百八十天到期。
- 提交后修改日记内容、拆掉整座星座以重新分配日记。

## 3. 视觉与交互设计

### 3.1 总体方向

关键词：深邃星空、安静、真实空间感、纸张质感、克制光效、清晰排版。需要高级而精致，不是把默认组件改成深色，也不是满屏发光和装饰卡片。

建议视觉默认，可根据真机效果调整：

- 深墨蓝为背景，暖白为正文，低饱和金色用于主要星光，少量冷蓝辅助区分空间层次。
- 首页和发现页沉浸，写作和阅读区域稳定、易读，第四页信息层级清楚。
- 每屏明确一个视觉主角，不同时堆大标题、说明卡、进度卡和多个主按钮。
- 四个页面共用一致的底部导航、图标语言、间距、圆角、字体层级和过渡方式。
- 建立可复用设计 tokens；首轮可采用 4/8 dp 间距体系、至少 48 dp 的交互区域、纸张正文约 17–19 sp，均为工程设计默认而非不可调整的产品规则。
- 星星视觉可以小，但命中区域不能小到难以操作；密集星座进入近景后再选择具体日记星星。
- 支持字体放大、中文长文本、系统栏安全区、键盘避让、图片比例变化和小屏设备。
- 主界面不使用占位 emoji 充当最终星球、星座或导航图标。情绪选项可以使用 emoji 表达含义，最终动效应统一制作。
- 字体、纹理、星球素材、音效等记录来源和许可；支持中文，不出现缺字方框。

### 3.2 动效原则

- 动效解释状态变化，而不是掩饰加载失败。
- 必须能取消、结束和恢复，不因重复手势、页面切换、前后台切换而叠加。
- 星球应有球面形变感、明暗、表面细节与大气层等立体依据；不要仅让一张平面图片在屏幕上转圈来宣称星球自转。
- 星座整体漂移，内部布局稳定。随机值初始化后持久使用，不能每次重组或每帧重新随机造成跳动。
- 星星冲向屏幕使用景深、缩放、拖尾和柔和光晕衔接；禁止刺眼的全屏硬闪。
- 纸页出现后降低背景运动，保持阅读舒适。
- 减少动态效果只简化呈现，不改变发现的摇晃触发规则。
- 震动和音效轻量且可关闭；设备没有震动能力不阻塞主流程。
- 隐私遮挡优先于任何退出动画，不能为了动画继续展示已失效的内容。

## 4. 第一页：星球首页

### 布局

- 左上角只放 App 名称“拾星”，不堆副标题、问候和数据。
- 中间偏下是一颗较大的完整立体星球。首轮可按屏幕宽度约 75%–85% 设计，再根据留白调整。
- 星球缓慢自转，用户可拖动调整观察角度，松手后逐渐恢复缓慢自转。
- 星球外观不因日记数量发生阶段成长。
- 周围显示用户选择的已完成星座，最多八座，可少于八座或不选择。
- 星球与星座独立运动，星座不粘在星球表面。
- 星座呈现远近层次和缓慢漂移，细线平时克制，选中后变亮。

### 交互

1. 点击一座星座：它适度靠近、突出，其他背景变暗，显示名称。
2. 点击其中一颗日记星星：打开对应的自己的日记。
3. 关闭日记：回到刚才的星座观察状态。
4. 点击空白区域：退出近景，恢复首页全景。

没有任何已完成星座时，仍显示完整、可欣赏的星球和背景星空，不伪造已完成星座。新完成的星座不自动替换用户已有的首页布置。

首页不是个人数据仪表盘，不出现等级卡、成长卡、写作进度或继续写作入口。

## 5. 第二页：发现日记

### 5.1 星空状态

这是持续、有纵深感的星空，不放首页的大星球。中心留给星星靠近与日记展开。右上角低调显示今日剩余阅读次数。

根据真实结果展示状态，示例文案：

- 定位或查询中：“正在寻找附近的星光…”
- 存在可读日记：“附近藏着星光，轻轻摇一摇。”
- 附近没有内容：“这里暂时没有留下的星光。”
- 附近内容都已遇见：“这里的星光，你都遇见过了。”
- 额度耗尽：“今天的十次相遇已经结束，明天再来拾星。”
- 快速乘车：“请停稳后，再遇见附近的星光。”

只提示可用状态，不向读者展示作者位置、附近精确数量或可枚举的日记清单。若服务端无法可靠区分“没有内容”和“都读过了”，使用诚实的统一空态，不编造结果。

### 5.2 唯一发现手势

日记只通过摇晃手机触发。不要添加按钮、点击中央星星、隐藏长按或其他面向用户的替代发现方式。

完整流程：

1. 在发现页空闲且符合条件时，检测到一次有意的轻摇。
2. 星空产生轻微波纹和柔和震动，进入请求状态。
3. 获得有效可读内容、媒体就绪并确认资格后，远处一颗星变亮，其余星光适度变暗。
4. 星星向屏幕中心靠近、逐渐变大，出现短拖尾与景深变化。
5. 柔和光晕展开，日记纸页显现。
6. 进入阅读状态，忽略后续摇晃。
7. 用户关闭后，纸页收拢为星光并退回星空。
8. 下一次必须重新摇晃，不自动打开下一篇。

请求失败或没有内容时，只做轻量反馈，不播放完整成功揭晓动画。传感器不支持时明确说明无法使用摇晃发现，其余适用功能仍可使用。测试构建可注入传感器事件，但不能因此在正式版本出现“点击拾星”。

### 5.3 发现资格

候选日记必须同时满足：

- 当前公开、审核允许展示、没有被删除或下架。
- 原始地点在读者当前位置 200 米范围内，且位置足够可靠。
- 不是读者自己写的，也不是读者屏蔽的作者所写。
- 当前账号以前没有成功打开过。
- 当日还有阅读次数，当前不存在冲突中的阅读请求。

在合格候选中随机选择，不默认按热度或最新排列。不得先把全体日记和坐标下载到客户端再过滤。

### 5.4 持续阅读范围：硬规则

200 米不仅是打开条件，也是持续阅读条件。实现明确的状态机：

- IN_RANGE：可靠位置确认在范围内，资格有效，可以展示。
- UNKNOWN：定位、连接或资格暂时无法验证，立即遮住正文和图片，暂停回应，显示确认提示。
- OUT_OF_RANGE：可靠位置确认超过 200 米，立即隐藏内容并结束本次阅读。
- ENDED：主动关闭、确认越界、验证超时、内容撤销等导致终止；该会话不可重新打开。

UNKNOWN 状态下，在同一阅读尚未结束时，重新验证仍在范围内，可以继续，不重复扣次。确认越界后，即使回到原地也不能恢复该篇；它仍然属于已遇见内容，不再随机出现。

不要增加允许越界继续看的宽限时间，不把业务半径偷偷扩大到 250 米，不靠旧缓存让正文保持可见。精度不足可以进入 UNKNOWN，但不能假装已可靠确认。

以上规则作用于阅读别人的日记。作者查看自己的日记不受 200 米范围限制。

### 5.5 每日十篇

- 每个账号每天最多成功打开十篇陌生日记，与星座进度无关。
- 无内容、加载失败或成功打开前失去资格，不应消耗一次。
- 成功打开以后，关闭、越界、断网或没有读完，都不返还该次，也不再抽到该篇。
- 预查询附近是否有内容、预加载、摇晃次数本身不等于成功打开。
- 自己的日记不限于此额度。
- 额度、已遇见记录和幂等请求由服务端管理，防止并发和重试重复扣次或超额。

需要在真实云端实现前明确“成功打开”的可实现边界：区分内容准备、服务端提交、客户端首次呈现和回执。解释通信失败窗口及恢复策略，不声称服务器能直接知道用户实际看见了屏幕。此处是需要设计和验证的工程问题，不能通过“请求一发出就扣次”偷换规则。

每日重置时区、未用次数是否结转尚未被单独确认。建议默认采用账号固定时区、服务端每日零点重置、不结转；将其列为建议默认，而不是既定决定，不在客户端依赖可随意修改的手机时间。

### 5.6 阅读纸页和情绪回应

使用作者保存的纸张、字体、照片和原始天气快照。文字可放大，不能修改原作。只显示模糊地点信息，不显示作者账号、头像或精确地点。

每位读者对每篇日记只能发送一种情绪回应，没有独立点赞：

- 给你拥抱：两道星光弧从左右环抱纸页，轻轻收拢、放松，配柔和震动。
- 我懂这种感觉：两颗小星靠近并同步闪亮。
- 谢谢你写下来：小星从选项升起，在纸页边缘留下短暂光迹。
- 愿你今天开心：纸页后方出现温暖的金色晨光。

统一美术语言，建议约一至两秒，不强制退出阅读。发送成功后才播放“已送达”动画；失败说明原因并支持幂等重试。成功后保留回应状态，不允许反复发送、改选刷动画或进一步聊天。

更多菜单提供举报和“不再遇见这位作者”。后者由后台执行身份级排除，但不向读者暴露作者身份，也不通知作者是谁屏蔽了他。

## 6. 第三页：写日记

### 6.1 布局与内容

进入页面直接书写，不先经过模板选择向导。

- 大面积纸张占据主体，边缘保留舒适留白。
- 顶部组织日期、天气和可选标题。
- 正文是主要区域，不能被工具栏和装饰挤压。
- 底部工具包含图片、字体、纸张和可见性选择，点击才展开对应控件。
- 底部有清楚的预览操作，键盘出现时仍能使用必要工具。

规则：

- 标题可选。无标题时，自己的列表可用日期时间识别，读者不必看到“无标题”。
- 正文至少十个字才能正式保存；标题和空白不计入最低要求。具体 Unicode 字符计数方法需前后端一致并测试，不用 UTF-16 长度错误计算表情。
- 未达要求的内容可以保留为草稿。
- 最多两张照片，支持图库和拍照；图片不能代替正文最低要求。
- 照片放在正文之后，一张居中，两张可并排，点开查看完整比例。
- 草稿阶段可以替换和删除照片，不制作复杂拼贴编辑器。
- 字体：清晰正文体、自然手写体、书籍衬线体。
- 纸张：暖白、复古牛皮纸、深蓝夜笺。
- 三种字体与三种纸张均免费直接选择，没有解锁条件。

### 6.2 天气背景

写作时获取当前地点天气，映射到预制视觉效果，不要求实时 AI 生成背景图片：

- 晴：柔和暖光、少量光点。
- 阴：低对比灰蓝云层。
- 雨：纸张外围雨丝、轻微雨滴元素。
- 风：外围光点或薄云有方向性移动。
- 夜：更深的星空和月光氛围，可与雨、阴等天气组合。
- 雷雨：以云雨和克制的明暗变化表达，不使用危险频闪。

效果不能降低正文对比度，输入时减少干扰。提交时保存天气快照，未来阅读不被今天的天气覆盖。获取失败使用中性背景和诚实状态，不能伪造实时天气。

### 6.3 预览、提交与不可修改

草稿自动保存，只有明确最终确认才正式提交：

写作 → 完整预览 → 核对内容、样式、照片、可见性和模糊地点 → 最终确认 → 验证与必要检查 → 正式保存成功 → 点亮星星。

预览中明确提示：“提交后，日记内容将无法修改。”可以返回草稿修改。

正式保存以后，标题、正文、照片、字体和纸张固定，不提供编辑按钮。作者仍可删除或切换公开状态。阅读字号调整只改变展示，不修改原作。

### 6.4 地点与可见性

- 默认公开，用户可主动选择私密，最终按钮清楚区分“公开发布”和“私密保存”。
- 公开提示“附近 200 米可发现”，并提醒文字和照片也可能暴露身份。
- 首次正式保存时，无论公开或私密，都必须联网、有有效定位，并通过停稳检查。
- 拒绝定位、位置不可靠或处于快速乘车状态时，不能正式保存、不能点亮星星，但可保留草稿。
- 锚点来自用户最终确认提交时验证的位置，不是开始写作的地点。
- 提交前展示模糊地点；如最终验证地点与预览明显变化，更新提示并让用户明确确认，不能偷偷在另一个地方发布。
- 审核处理时间不能把原锚点改成审核完成时的位置；记录用户最终提交的地点及天气快照。
- 正式公开后没有自动到期，不设置固定公开延迟；通过必要检查后即可被合格读者发现。
- 公开转私密可以远程操作，不需要回到原地。
- 私密转公开也可以在任何地方操作，不重新要求到场或当前定位；仍使用原锚点、原日期、原天气、原内容，并经过必要的公开内容检查。
- 切换可见性不是创建新日记，不生成新星星、不重置已读记录和情绪回应。
- 公开失败不能静默改成私密成功。

### 6.5 草稿和提交一致性

- 自动保存文字、图片引用、样式等草稿状态，重启后能够恢复。
- 图库临时权限、照片临时文件和进程结束不能轻易使草稿图片失效。
- 网络、上传或审核失败提供可理解的反馈，不让用户重新写。
- 未正式成功的新提交可保留可编辑草稿；已正式保存的日记，即使重新公开被拒，也不能因此绕过内容不可修改规则。
- 提交使用稳定请求 ID 和状态查询；超时重试前核对结果，不能产生重复日记、重复星星或重复上传。
- 提交结果不确定时先展示确认中，不假装失败后又创建一篇，也不假装成功播放点亮。
- 不因网络恢复而自动公开旧草稿；用户重新确认后，重新验证实际提交地点。

## 7. 第四页：我的星座

### 7.1 三层模型

明确区分：

1. 星座类型：星座名称和简化图案模板。
2. 星座实例：用户收藏的某一种星座的第一座、第二座等，有独立进度和日记。
3. 首页展示关系：哪些已完成实例被选中在首页显示。

一个类型最多保留五个实例，已完成和未完成都计入。首页最多展示八个已完成实例，跨所有类型计算。这两个限制与每日十篇阅读额度没有关系。

星座采用真实星座作为依据、适度简化图案。实际目录、点位数与顺序尚待设计验证：不要编造天文学事实，记录参考与简化方式，也不要把某个星群未经说明当作独立正式星座。

### 7.2 页面组织与点亮

- 纵向浏览的星座画卷，连续星空背景，不使用难以定位的无限平移星图。
- 当前目标在上方较大展示，显示名称与点亮进度。
- 下方能区分其他未完成、已完成及首页展示中的实例。
- 一次只有一个当前目标，用户可自由切换；已有日记不随切换搬家。
- 每篇成功保存的合格日记只对应一颗星，公开和私密一样，不限于每天第一篇；每日十篇限制仅用于发现阅读。
- 新日记进入当前目标的下一个可用位置，既有日记位置保持稳定。
- 保存成功后，光点从纸页升起，进入星座空位，相邻连线逐渐亮起；普通点亮后停留在已保存日记，不强制跳页。
- 完成整座时播放整体点亮动画，提供去布置首页的入口，不擅自占位或替换。
- 第一次保存时若尚未选择目标，轻量询问星座归属；可以稍后选择，日记保留一颗待安放的星。
- 未选择目标的日记在第四页可找到、可阅读、可后续安放；不能成为无法访问的数据。

### 7.3 布置首页

第四页提供“布置首页”，展示已完成实例、当前选择和“已选择 x / 8”。确认后更新首页。

- 可以选择零至八座，未完成星座不可选。
- 八座已满时需由用户取消一个或明确替换，不能自动轮换。
- “取消首页展示”只移除展示关系，第四页该实例仍保持完成，日记不变。
- 不因此释放同类型五座的收藏名额。
- 不实现“拆掉整座星座，把所有日记退回待安放”的功能。

### 7.4 删除单篇与回应

- 删除日记前确认：“删除这篇日记，也会熄灭它对应的星星。”
- 删除后只熄灭对应位置，其他星星和日记不动。
- 原本已完成的星座变成未完成，从首页撤下，第四页保留原实例及剩余进度。
- 以后选择它，可以用新日记填补空位。
- 转私密不熄灭星星，取消首页展示也不熄灭星星。
- 有未查看回应时，第四页入口出现小金点，相关日记星星柔和发亮；待安放日记也要能找到回应。
- 打开日记显示一次对应的到达动画和匿名提示，如“一位曾路过这里的人，给你留下了一个拥抱。”
- 多条回应聚合，不连续播放一长串动画；随后保留匿名计数，查看后清除未读提示。

所有星座类型都达到五座且全部填满的容量耗尽情况，用户明确要求暂不考虑。不要自行添加无限复制、容量付费、拆解、删除旧日记或禁止继续记录的产品规则。将此列为后续边界决策，不阻塞当前视觉原型；也不能为绕过它违反五座上限或丢失数据。

## 8. 定位、运动与手机能力

### 8.1 定位

优先评估 Android 融合定位方案，并明确目标设备是否依赖 Google Play 服务。实现前检查当前官方文档及兼容性。

不能把取得一次经纬度等同于可靠到场。统一处理权限精度、定位开关、样本时间、精度估计、连续稳定性、速度、活动状态、超时和生命周期。

需要测试室内漂移、边界附近、陈旧定位、从近似定位切到精确定位、定位中断和车内移动。业务半径固定 200 米；位置可靠性阈值、采样频率和未知状态超时是可配置的工程默认，先提出并记录依据。

GPS 和融合定位存在误差。不能保证真实物理距离零误差或跨线零延迟；精度数值也不是绝对误差上界。服务端验证上报位置，不等于证明硬件位置无法伪造。模拟位置标记、活动状态等只能辅助评估，不能声称完全堵住伪造定位。

不要依赖低频围栏事件独自实现读中即时范围控制。前台阅读要持续校验，及时隐藏；记录采样、网络与撤销检测延迟的实际测量结果。

### 8.2 活动识别

- 用于辅助识别快速乘车，暂停发现及首次公开/私密正式保存。
- 不要求计步，也不要求用户必须步行进入范围；已经在现场停稳的用户可以使用。
- 拒绝活动识别权限或设备不支持时，以连续定位的移动与稳定性辅助判断，判定不清就暂缓相关操作。
- 不反复弹出授权请求。活动识别权限与定位权限分别说明。

### 8.3 摇晃

- 加速度信号需去除或分离重力影响，识别有意摇晃，而不是简单对一个原始数值设阈值。
- 处理采样间隔、时间窗口、去抖、冷却、一次手势只触发一次，以及放桌上、拿起手机、走路等误触发。
- 仅发现页空闲且资格允许时接受发现手势，其他页面不触发。
- 仅在需要时订阅传感器，离页和后台释放资源。
- 如评估陀螺仪辅助，先说明对现有摇晃识别的实际价值和测试证据；不要仅注册监听就声称增加了一个有深度的传感器功能。

### 8.4 其他能力及范围

相机用于拍照，图库用于选图，触摸用于普通页面操作，震动用于反馈。诚实区分硬件传感器、推断服务和输出设备：活动识别不自动等于另一个独立硬件传感器，震动马达不是输入传感器，天气 API 也不是手机传感器。

如果课程完整 rubric 要求三至五个传感器且当前设计覆盖不足，明确列为待解决的课程风险，提出最小改动建议供我决定。不要偷偷加步数计、恢复旧星星包，或谎称传感器要求已经全部满足。

## 9. 断网、后台与权限异常

- 断网可以写草稿、查看本机已有的自己的日记和星座；不承诺未缓存记录也能打开。
- 断网不发现新陌生日记、不首次正式保存、不发送回应。云端可见性变化不能只改本地后假装成功。
- 读中断网按 UNKNOWN 先遮住，验证恢复且会话未结束才能继续；持续失败则结束。
- 切后台、锁屏、进程重建时不能泄露陌生日记正文或留下可直接绕过验证的恢复路径。回前台先遮挡并重新验证；已结束会话不能复活。
- 后台无法确认期间不能推断用户一直没离开过。说明这个观测边界，并在真实阅读实现前提出最小化的会话暂停/终止方案。
- 拒绝定位：不能发现或首次正式保存任何日记；可用本机草稿和自己的已有记录。
- 相机或图库不可用只影响图片添加，天气失败只影响天气效果，不能因此破坏纯文字草稿。
- 拒绝运动权限不等于拒绝位置权限；不把所有能力打包成强制授权。
- 不使用后台自动发布和恢复网络即发送的隐藏队列。

## 10. 匿名身份、云端权限和内容安全

### 10.1 匿名身份

首次打开无需注册即可进入首页，后台创建私有匿名身份，管理日记、星座、额度、已读、回应和屏蔽。

可提前绑定恢复方式，以便跨设备恢复。具体登录提供商后续选择，核实真实 SDK 支持，不虚构接口。说明未绑定前卸载、清数据、丢失设备可能导致无法恢复；不能承诺事后凭空找回。对外不展示真实身份或公开个人主页。

匿名身份重建仍有滥用风险，不能把同一账号限额说成绝对的每个自然人限额。记录限流和滥用处理的边界。

### 10.2 数据访问

- 精确日记锚点、作者身份、举报人身份和管理信息置于受保护的服务端数据域。
- 阅读别人日记的响应不返回作者稳定身份标识、精确经纬度、精细 geohash 或能关联作者的存储路径；使用必要的不透明内容或会话标识。
- 距离筛选、权限、审核状态、已读排除、屏蔽和额度由服务端执行。
- 不允许客户端直接列举所有公开日记并下载正文；正文和图片都受当前阅读资格约束。
- 私密内容只对作者和明确授权的必要管理流程可见，不公开暴露。
- 不用永久公开图片链接绕过正文的访问控制；设计受限媒体获取、缓存生命周期和撤销策略。
- 陌生日记不要持久化为可离线反复阅读的本地档案，内容失效时清理阅读层可访问缓存。
- 手机已经接收到的内容可能被截屏、另机拍摄或受控设备截取。说明这类边界，不承诺绝对无法复制或远程抹除。
- 不记录作者后续移动轨迹，不在常规日志、分析事件或崩溃报告中泄露正文和精确坐标。
- 可见性修改、删除、审核下架要使既有阅读资格失效；前台同步与复核机制需要实测，不能只更新数据库而不影响已打开的页面。

### 10.3 图片和审核

- 上传前处理图片大小、方向和 EXIF 位置等元数据，提醒用户避免人脸、车牌和私人信息。
- 公开内容经过必要文字和图片检查。检查中、待人工复核、失败、通过分别展示真实状态，不伪装即时成功。
- 自动检查是初筛，不声称可以识别全部违规内容。没有真实审核服务时，开发环境可以明确模拟，生产环境不能将模拟通过当作审核已完成。
- 私密正文不因为“顺便审核”而默认发送给未披露的外部服务；如需扩展数据处理范围，先说明并获得决定。
- 举报支持隐私泄露、骚扰攻击、不当内容、广告垃圾等分类及补充说明。
- 单次举报或达到某个数量，不自动等于违规，不自动全局删除。
- 简易管理后台提供查看举报、维持公开、下架、复核、处理记录；明确人工负责人由团队指定，不编造成员姓名。
- 作者能查看处理原因和提出申诉；读者只看到内容已不再公开，不看到举报人和管理细节。
- 作者屏蔽立即对当前用户生效，不向双方公开身份关系。
- 管理后台使用独立授权，不能在用户 APK 中嵌入管理员凭证。

## 11. 技术方案：建议默认，不锁死过时版本

优先采用原生 Kotlin、Jetpack Compose、Android Studio 和 Gradle；不改成 iOS、Flutter、React Native 或网页套壳。具体 Android SDK、JDK、AGP、Kotlin 和库版本按当前环境与官方兼容性验证，先检查已有配置，不凭空写“最新版本”。

建议架构：单向状态流、ViewModel、可替换 Repository、Coroutines/Flow、本地结构化持久化及独立传感器/定位服务。不要把整个应用、业务规则和网络请求塞进一个巨型界面文件。

建议云端评估 Firebase Authentication、Firestore、Storage 和 Cloud Functions；天气采用真实可用且条款允许的服务。这是实现建议，具体地区、费用、配额、设备支持和部署方式需要检查。密钥和管理员凭证不提交到仓库。

数据模型至少区分：

- 用户身份与偏好。
- 本地草稿、提交操作及状态。
- 不可变日记内容、受保护地点、可见性与审核状态。
- 天气快照与受限媒体资产。
- 星座类型、实例、日记星位、首页展示关系。
- 阅读会话、已遇见记录、每日额度。
- 一次性情绪回应、作者未读提示。
- 屏蔽、举报、处理记录与申诉。

为创建日记、点亮星位、扣次、发送回应和删除相关状态设计幂等与并发处理。明确哪些必须原子提交、哪些异步补偿，数据库规则和存储权限都需要测试。

开发/演示模式与真实云端模式明确分离。演示数据可以帮助视觉预览和自动化测试，但必须标识来源，不能声称本地伪随机数据就是跨用户云端发现。演示入口、调试定位、传感器注入不得进入正式发布体验。

最先完成一个端到端纵向闭环，再扩展目录和美术资源：

> A 在真实地点写日记 → 云端保存并点亮一次 → B 在范围内摇晃读到 → B 发送一次回应 → A 收到 → B 越界内容隐藏 → A 转私密后其他人不可发现。

## 12. 性能、可用性与视觉验收

不要用“高级”“流畅”“上线级”代替测量。提出目标并记录实际设备、系统、构建类型和测量方式。

- 在选定中端真机上以接近稳定 60 fps 为首轮动效目标，记录卡顿和长帧；未达到要降低粒子、模糊或纹理成本，不只提高手机要求。
- 动画使用帧时间而非每帧固定步长，避免不同刷新率速度不一致。
- 不在主线程执行图片处理、数据库重工作和网络访问。
- 页面退出后停止无用渲染、定位和传感器订阅；避免前后台重复监听。
- 输入长文、键盘展开、两张大图、系统大字号时仍可编辑、预览和提交。
- 大号星球不被导航遮住，星座不长期遮挡关键文字，纸张不透明到看不清正文。
- 正常、空、加载、无权限、无网络、低精度、失败、成功、额度耗尽都有设计，不只做有内容的截图。
- 支持文本与交互可访问性；发现手势不提供点击替代是已定约束，应诚实说明由此存在的运动能力可用性限制，不宣称全面无障碍。
- 在模拟器检查布局，在真机验证摇晃、定位、活动识别、相机、震动及耗电。不能把模拟器注入的测试当作真实传感器证据。
- 实际渲染并检查四页截图；动画还需短录屏或真实运行检查，不能仅凭静态截图认定动效正确。

## 13. 必须覆盖的验收场景

给需求和测试建立可追踪编号。以下是最低验收集合，不代表可以省略安全测试：

1. 首页只有固定星球和选中星座，不出现成长、星星包或继续写作入口。
2. 星球真实呈现自转空间感；星座稳定漂移，选中和返回状态正确。
3. 首页最多八座；取消展示后第四页仍完整；未完成实例不能选择。
4. 同类型五个实例含未完成实例，不能创建第六个来绕过限制。
5. 正文九字不能正式提交，十字可以；无标题可以；第三张图片不能加入。
6. 公开为默认；公开与私密首次保存都需要有效定位和停稳；拒绝定位只能保留草稿。
7. 预览可返回修改，最终成功后内容和样式不可编辑；一次提交重试不重复生成星星。
8. 从地点 A 提交后，身处地点 B 将私密转公开，锚点仍为 A，不要求回到 A。
9. 天气快照不会被以后天气覆盖；服务失败呈现中性状态。
10. 摇晃才触发；点击星空无效；摇晃请求中和阅读中不会重复开篇。
11. 无内容或加载失败不播放完整成功动画、不扣次；只返回合格且未遇见的他人日记。
12. 测试位置输入在半径内、恰在边界、半径外及精度不可靠时的分类；不把模拟边界测试声称为真机零误差证明。
13. 可靠越界先隐藏正文和图片、禁用回应；重新回范围不能恢复原日记。
14. UNKNOWN 先遮挡，资格恢复且会话未结束可以继续；会话终止后不能恢复。
15. 第十次成功打开后不能打开第十一篇；并发、重试和多设备不会绕过同一账号限额。
16. 每人每篇仅一次情绪回应；失败不显示已送达，成功动画不强制关闭阅读；作者聚合和未读提示正确。
