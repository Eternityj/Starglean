# Backend Files

This directory contains the backend source files maintained by the project; **it is not a cache directory**. Organizing local files does not change the live project. Do not rerun migrations, empty the database, or delete Storage resources as part of a file cleanup.

| Path | Purpose | Retention guidance |
| --- | --- | --- |
| `migrations/` | Database migrations, ordered by the timestamp prefix in each filename; includes permissions, publication, the 200-meter limit, quotas, capacity, and locking rules | Do not delete files just because they have already been deployed |
| `functions/nearby-private-media/` | Edge Function and tests for private photo validation, retrieval, and deletion | Keep |
| `tests/` | Database contract and boundary assertions | Keep; confirm the target environment and scope of transaction cleanup before running |
| `schema/` | Review summaries for understanding the protocol; `complete_public_app_contract.sql` references migrations in order | Keep; this is not a second set of migrations and must not be deployed again |
| [email-templates/](email-templates/README.md) | HTML templates for signup, login, and email-change verification codes | Keep |
| `client-config.properties` | Public project URL and publishable key used by Android builds and tools | Required; never add service-role or administrator keys |
| [OPERATIONS.md](OPERATIONS.md) | Operational procedures for service controls, report handling, deletion, and free-tier quotas | Keep |
| `.temp/`, `.branches/` | Local state generated by the CLI | Ignored; the earlier cleanup removed only the existing `.temp/` directory |

Suggested reading order: start with the operations guide to understand the system boundaries, then review `schema/` and the client protocol in `core/network/`. Finally, follow the migrations in order and review `tests/` to understand the history and assertions. Do not rename, reorder, merge, or delete deployed migration files.
